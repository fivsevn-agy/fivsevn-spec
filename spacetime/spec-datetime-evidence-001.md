# Datetime Evidence Specification  
# 时间戳的证据与严格使用规范

本文定义严格语境下时间戳的使用原则。  
核心规则是：只有能够表示时间轴上唯一一刻、且包含明确时区信息的时间表达，才能作为严格时间戳使用。

## 1. 规范目的

本文用于约定在严格语境下，时间戳应当如何使用，以及它能够承担什么责任、不能承担什么责任。

这里的严格语境包括但不限于：

- 版权；
- 合规；
- 纠纷；
- 审计；
- 发布时间核验；
- 事件顺序还原；
- 系统记录比对。

在这些场景中，时间不只是普通记录，而可能参与核验、说明、对照或证明。  
因此，必须使用能够明确定位到时间轴唯一一刻的格式。

---

## 2. 严格时间戳的定义

在本规范中，只有满足以下条件的时间表达，才被视为严格时间戳：

- 表示时间轴上的唯一一刻；
- 包含明确的时区信息；
- 不依赖上下文即可被第三方理解；
- 可以与其他系统时间进行对齐和比较。

对应格式为：

```text
YYYY-MM-DDTHH:mm:ss±HH:MM
```

示例：

```text
2025-04-09T03:31:31+08:00
```

该格式包含：

| 部分 | 含义 |
|---|---|
| `YYYY-MM-DD` | 日期 |
| `T` | 日期与时间的分隔符 |
| `HH:mm:ss` | 时、分、秒 |
| `±HH:MM` | 时区偏移 |

只有包含完整日期、具体时间和时区偏移的时间表达，才具备严格时间戳的基本条件。

---

## 3. 适用范围

以下场景中，时间可能承担核验或证明作用，应使用严格时间戳：

- 作品发布时间；
- 首次公开时间；
- 系统自动生成的创建时间；
- 系统自动生成的修改时间；
- 数据提交时间；
- 数据确认时间；
- 内容发布时间；
- 关键事件发生时间；
- 事件发生顺序的还原；
- 审计或合规记录。

在上述场景中，不应使用只有日期、没有时区或依赖上下文解释的时间写法。

---

## 4. 时区要求

### 4.1 必须包含时区

严格时间戳必须包含时区信息。

推荐格式：

```text
2025-04-09T03:31:31+08:00
```

不推荐，也不得作为严格时间戳使用：

```text
2025-04-09 03:31:31
```

原因是，不含时区的时间字符串存在以下问题：

- 无法确定所处时区；
- 无法与其他系统时间准确对齐；
- 无法跨地区、跨系统稳定比较；
- 不具备充分的可验证性。

因此：

```text
不含时区的时间不得作为严格时间戳使用。
```

---

## 5. 自动生成优先原则

在证据、合规或核验语境中：

```text
系统自动生成的时间戳
```

优先于：

```text
人工填写或手动修改的时间
```

原因在于：

- 自动生成时间更易追溯；
- 自动生成时间更容易与日志对应；
- 自动生成时间可与服务器时间、版本记录、发布系统记录交叉验证；
- 人工填写时间更容易出现误差、遗漏或事后修改。

这并不意味着人工填写的时间完全无效，而是说明：  
当时间需要承担核验责任时，应优先采用系统生成、可追踪、可交叉验证的时间记录。

---

## 6. 文件名时间的定位

文件名或路径中的时间标记，例如：

```text
20251213
```

只是一种管理与定位辅助信息。

它具有以下特点：

- 不表达具体时刻；
- 不声明时区；
- 易于复制；
- 易于重命名；
- 可能由人工手动创建或修改。

因此：

```text
文件名时间不承担证明责任。
```

它可以用于排序、归档和定位，但不应作为发布时间、创建时间或事件发生时间的证据。

---

## 7. 多点一致性建议

在可能涉及核验的场景中，建议同一时间点在多处形成记录。

例如：

- 内容系统中的发布时间；
- Git 提交时间；
- 自动构建日志；
- 发布平台记录；
- 服务器日志；
- 外部归档或索引记录。

多个系统记录之间保持一致，可以增强时间信息的可信度。

需要注意的是，多点一致性是增强可信度的实践建议，不等同于自动产生法律效力。  
其作用在于让时间记录更容易被核验、比对和解释。

---

## 8. 证据边界

严格时间戳可以提高时间记录的明确性和可验证性，但它本身并不自动构成完整证据。

本规范的立场是：

- 严格时间戳可用于技术层面的时间定位；
- 严格时间戳可用于系统记录之间的比对；
- 严格时间戳可辅助说明事件发生顺序；
- 严格时间戳不能单独证明全部事实；
- 严格时间戳不替代法律、平台、机构或第三方认证要求。

本文档不构成法律意见。  
本规范不评估法律效力，只定义技术与实践层面的可验证性要求。
