# Date and Time Format Specification  
# 日期与时间书写规范

本文定义 fivsevn 体系中日期与时间的三层书写规范。  
本规范的核心原则是：不同场景使用不同时间格式，各层级之间不得互相替代。

## 1. 规范目的

本文用于约定不同使用场景下的日期与时间书写方式，以避免含义混淆和格式滥用。

在 fivsevn 体系中，日期与时间并不统一为单一格式，而是按照用途分为不同层级。  
每一种格式只服务于自身场景，不承担超出其设计范围的功能。

本规范尤其用于区分：

- 个人记录中的日期；
- 文档命名和内容归档中的日期标记；
- 系统、发布、核验语境中的严格时间戳。

---

## 2. 总体原则

时间写法应遵循以下原则：

1. **按场景使用**  
   不同时间格式服务于不同场景，不应为了表面统一而混用。

2. **避免歧义**  
   容易在地区、系统或语境之间产生误读的格式，不作为推荐写法。

3. **保留层级边界**  
   日期记录不是时间戳；文件名日期不是证据时间；严格时间戳必须包含时区。

4. **长期稳定**  
   一旦选定某一层级的写法，应在同类场景中长期保持一致。

---

## 3. 时间写法层级

时间相关写法按用途分为三层。  
三层之间互不替代，也不应跨层级滥用。

---

### 3.1 Level 1：日期记录

| 项目 | 内容 |
|---|---|
| 用途 | 手写笔记、日常记录、更新说明 |
| 是否为时间戳 | 否 |
| 是否参与系统计算 | 否 |
| 是否表达具体时刻 | 否 |

规范格式：

```text
YYYY.MM.DD
```

示例：

```text
2025.12.13
```

使用规则：

- 仅表示“某一天”；
- 不表达具体时间；
- 不要求时区信息；
- 适合个人记录和人工阅读；
- 作为个人记录习惯长期保持稳定。

Level 1 的意义在于简洁、清楚、稳定。  
它适合记录“日期”，但不适合承担系统时间、发布时间或证据时间的功能。

---

### 3.2 Level 2：日期标记

| 项目 | 内容 |
|---|---|
| 用途 | 文档标题、内容分组、资料归档、文件命名 |
| 是否为时间戳 | 否 |
| 是否表达具体时刻 | 否 |
| 是否要求时区 | 否 |

规范格式：

```text
YYYYMMDD
```

示例：

```text
20251213
```

使用规则：

- 使用纯数字；
- 不使用任何分隔符；
- 固定宽度；
- 天然支持字典序排序；
- 适用于文档命名与内容组织；
- 不表达具体时刻。

Level 2 的意义在于排序和归档。  
它可以帮助文件、资料或内容按日期排列，但不应被理解为某个事件发生的精确时间。

---

### 3.3 Level 3：严格时间点

| 项目 | 内容 |
|---|---|
| 用途 | 系统字段、发布时间、事件时间、核验时间 |
| 是否为时间戳 | 是 |
| 是否具备唯一性 | 是 |
| 是否要求时区 | 是 |

唯一推荐格式：

```text
YYYY-MM-DDTHH:mm:ss±HH:MM
```

PHP 输出格式：

```text
Y-m-d\TH:i:sP
```

示例：

```text
2025-04-09T03:31:31+08:00
```

使用规则：

- 必须包含日期；
- 必须包含具体时分秒；
- 必须包含时区信息；
- 禁止使用不含时区的时间字符串；
- 推荐由系统自动生成；
- 用于需要精确表达时间轴上唯一一刻的场景。

Level 3 是严格时间戳。  
它适合用于发布时间、系统记录、事件顺序、审计、合规和其他需要核验的场景。

---

## 4. 使用对照表

| 场景 | 使用层级 | 推荐格式 | 示例 |
|---|---|---|---|
| 笔记、手写记录、日常更新说明 | Level 1 | `YYYY.MM.DD` | `2025.12.13` |
| 文档命名、内容归档、资料分组 | Level 2 | `YYYYMMDD` | `20251213` |
| 发布、系统记录、事件时间、核验场景 | Level 3 | `YYYY-MM-DDTHH:mm:ss±HH:MM` | `2025-04-09T03:31:31+08:00` |

---

## 5. 非推荐写法说明

以下写法在不同地区或个人习惯中广泛存在，但不作为本规范推荐格式。

### 5.1 美式日期顺序

```text
MM/DD/YYYY
12/13/2025
```

### 5.2 欧式日期顺序

```text
DD/MM/YYYY
13/12/2025
```

### 5.3 短年份写法

```text
YY.MM.DD
25.12.13
```

### 5.4 其他分隔符示例

```text
2025-12-13
```

说明：

- 上述写法仅用于理解他人记录或历史资料；
- 不要求、也不建议在本规范体系内使用；
- 其中部分格式在跨地区、跨语境时容易产生歧义；
- `2025-12-13` 虽然常见，但在本规范中不作为个人记录格式，也不作为严格时间戳使用。

---

## 6. 规范立场

本规范不强求所有场景统一为一种格式。

相反，本规范明确区分三种用途：

```text
记录日期      → YYYY.MM.DD
命名和归档    → YYYYMMDD
严格时间戳    → YYYY-MM-DDTHH:mm:ss±HH:MM
```

每一层级只解决自身问题。  
禁止把低层级日期当作高层级时间戳使用。

尤其需要注意：

- `2025.12.13` 不是时间戳；
- `20251213` 不是时间戳；
- `2025-04-09T03:31:31+08:00` 才是严格时间戳。

---

## 7. 与严格时间戳规范的关系

本文定义日期与时间写法的层级。  
涉及证据、合规、审计、发布时间、事件顺序还原等严格场景时，应同时遵循：

```text
spec-datetime-evidence-001.md
```

其中对严格时间戳的唯一性、时区要求、自动生成优先原则和证据边界作进一步说明。
